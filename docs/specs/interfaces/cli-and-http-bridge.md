# CLI Commands, Synchronous Control Bridge, and Auth Runners

## Purpose and boundaries
Provides the `opendrive` binary CLI, the shared synchronous `Bridge` connecting `AppController` (`opendrive-core`), `SyncEngine` (`opendrive-sync`), `SecretStore` (`opendrive-auth`), `MediaStreamServer`, and `MountManager`, background desktop authentication runners (`auth_runner`), persistent directory/store initialization helpers (`ui.rs`), and the optional `tray` runner.

- **In scope**: Synchronous CLI argument dispatch (`"" | "ui"`, `--self-check`, `authorize`, `list-root`, `status`, `mount`, `--mount-watchdog`, `tray`, `explore`, `sync-down`, `sync-up`, `sync-clear`, `open-item`, `stream`, `rename`, `rm|delete`, `cp|copy`, `mv|move`, `help|--help|-h`); localhost HTTP/1.1 range streaming (`MediaStreamServer` in `media_server.rs`); `Bridge` explorer/sync/file-op/batch/open-with operations (`explorer_ops.rs`, `explorer_file_ops.rs`, `explorer_batch.rs`, `explorer_open.rs`, `explorer_helpers.rs`); synchronous `Bridge` state snapshots (`bridge_types.rs`), secret store wiring, and mutations (`bridge.rs`, `bridge_vault.rs`); `MountBackend` (`backend.rs`, `live.rs`, `virtual_drive.rs`) & `MountManager` (`mount_manager/mod.rs`, `sync_ops.rs`); `AuthEndpoints`, `AuthSession`, `start_browser_oauth`, `start_service_account_auth` (`auth_runner/*`); and system tray loop (`shell/tray_loop.rs`).
- **Out of scope**: OAuth PKCE / Service Account JWT primitives (`opendrive-auth`), Drive HTTP transport (`opendrive-drive`), OS VFS adapters (`opendrive-fs-*`), and `eframe`/`egui` widget rendering (`design/*`, `desktop/*`).

## Observable behavior

### CLI Entrypoints (`main.rs`, `runtime/cli.rs`, `cli_commands.rs`, `cli_self_check.rs`, `ui.rs`)
- **Default (`""` or `"ui"`)**: Runs `ui::run_desktop_ui(ui::load_controller())` synchronously without spawning any Tokio runtime threads, launching the native `eframe` desktop window directly.
- **`--self-check` (`cli_self_check.rs`)**: Starts an in-process mock Drive server and runs end-to-end checks for `SyncEngine`, `StreamCache`, `MediaStreamServer` (`206 Partial Content`), `OpenWithRule`, `explorer_open_item`, `explorer_sync_down`, `explorer_sync_up_and_clear`, `explorer_sync_up`, `explorer_{rename,copy,move,delete}_item`, and `compute_explorer_quota`.
- **Interactive Admin / Mount / Watchdog / Tray (`main.rs`, `runtime/cli.rs`)**: `tray` (`--features tray`), `authorize <client_id> <client_secret>`, `mount <access_token> [path]`, and hidden `--mount-watchdog <pid> <mount_root> [letter]` live in `main.rs`; `list-root <access_token>` (`list_root_with_base`), `status` (`status_cmd`), and `help|--help|-h` live in `runtime/cli.rs` (with `dispatch_bridge` for testable CLI routing).
- **Headless Explorer & Streaming (`runtime/cli.rs`, `cli_commands.rs`)**:
  - `explore <account> [remote_path]`: Lists children with size, `NodeState`, and UTC modified timestamp.
  - `sync-down <account> <remote_path>`: Downloads a file or recursive folder locally via `Bridge::explorer_sync_down`.
  - `sync-up <account> <local_path> [remote_parent]`: Uploads a local file or recursive directory via `Bridge::explorer_sync_up`.
  - `sync-clear <account> <remote_path>`: Uploads/verifies and clears local replicas via `Bridge::explorer_sync_up_and_clear`.
  - `open-item [--dry-run] <account> <remote_path>`: Resolves `OpenWithRule` / OS default target (and launches unless `--dry-run`, waiting for `Ctrl+C` in interactive streaming mode so the localhost `MediaStreamServer` stays live).
  - `stream [--probe] <account> <remote_path>`: Pre-warms head/tail chunks, starts `MediaStreamServer`, prints the localhost URL, optionally sends a `Range: bytes=0-65535` probe asserting `206 Partial Content`, and waits on `Ctrl+C` in `dispatch` mode so players can keep streaming.
  - `rename <account> <remote_path> <new_name>`, `rm|delete <account> <remote_path>`, `cp|copy <account> <remote_path> [dest_folder]`, and `mv|move <account> <remote_path> <dest_folder>` (`explorer_file_ops.rs`): Delete (Trash + local remove), rename, copy, and move Cloud or Local files/folders in lockstep via `Bridge::explorer_{delete,rename,copy,move}_item`.

### Localhost HTTP/1.1 Streaming Server & Explorer Operations (`media_server.rs`, `explorer_ops.rs`, `explorer_file_ops.rs`, `explorer_helpers.rs`, `explorer_open.rs`)
- `MediaStreamServer::start(engine, rt)` binds `127.0.0.1:0` with a random UUID session token and exposes `/stream/<token>/<node_id>/<encoded_name>`. Rejects invalid methods/tokens with `403 Forbidden`, missing/trashed/folder nodes with `404 Not Found`, and invalid ranges with `416 Range Not Satisfiable`. Supports `GET` and `HEAD` with `Accept-Ranges: bytes`, `Cache-Control: no-store`, `Content-Type` inference (`content_type_for`), `parse_http_range` (`bytes=start-end`, `bytes=start-`, `bytes=-suffix`), and `512 KiB` streaming chunks backed by `SyncEngine::read_cached_range(node_id, offset, want, 3)`.
- `Bridge::explorer_root_node`, `explorer_list`, `explorer_local_entries`, `explorer_sync_down` (reconciling Windows CFAPI placeholder dirs if mounted), `explorer_sync_up` (enforcing `!read_only`), `explorer_sync_up_node` (in-place node upload, enforcing `!read_only`), `explorer_sync_up_and_clear` (enforcing `!read_only` and calling `MountManager::dehydrate_path` post-verify), `explorer_{delete,rename,copy,move}_item` (enforcing `!read_only` + Cloud/Local sync + placeholder reconciliation), `explorer_{sync_down,sync_up,sync_clear,delete,copy,move}_batch` (`explorer_batch.rs`, returning `BatchOutcome` with `succeeded_ids` + partial-progress errors), `explorer_stream_url` (pre-warming head + tail chunks), `explorer_open_item`, `update_open_with_rules` (validating and persisting unique `Settings::open_with_rules`), `remove_open_with_rule` (deleting a rule by index even when legacy duplicates exist), and `update_explorer_folder_cache` (toggling `Settings::explorer_folder_cache`).

### Synchronous Bridge, Secret Wiring & Mount Manager (`bridge*.rs`, `ui.rs`, `mount_manager/*`)
- `Bridge::new_with_secrets`, `with_data_dir`, `with_mount_manager`, `state_snapshot`, `add_account`, `account_action` (including `"move_up"` / `"move_down"` order persistence), `modify_settings`, `update_settings`, `update_virtual_drive`, `evict_cache`, `rename_account`, `export_encrypted_vault`, `import_encrypted_vault`, and `spawn_mount_sync` coordinate controller state, `SecretStore`, `SyncEngine`, and `MountManager`.
- `ui::build_bridge_in_dirs_with_secrets` and `build_persistent_bridge` configure `SyncEngine::set_stream_cache_dir(<data_dir>/stream_cache)` when `data_dir` is present, and `build_persistent_bridge` installs process console/close cleanup guards (`install_process_mount_guards`) and reconciles disabled `This PC` namespace state on startup.
- `MountBackend` (`backend.rs`, `live.rs`) supports `unregister_account`, `unregister_all_accounts`, `dehydrate_path`, `cleanup_legacy_subst`, and `sync_this_pc_namespace`; `live.rs` hosts `cleanup_os_mounts`, `cleanup_os_mounts_for_pid` (checking `<data_dir>/mount-owner.pid` + `is_process_alive` so a newly restarted instance's mounts are never torn down), `install_process_mount_guards`, and `spawn_mount_watchdog` (spawning `--mount-watchdog` via `spawn_detached_background` without mutually exclusive Win32 flags, called on `connect_account`, `set_virtual_drive`, `sync_this_pc_namespace`, and Windows `mount` CLI) so unexpected app kills or `Ctrl+C`/console closes still unregister CFAPI roots and clear virtual drives/`This PC` entries, while `MountManager::shutdown_all` tears down mounts cleanly on exit or `Drop`.
- `start_browser_oauth` and `start_service_account_auth` run in background worker threads (detecting unexpected disconnects via `AuthSession::try_recv`), awaiting `complete.rs` async avatar caching before finishing `finish_or_update_account` (preserving updated `nickname` and `read_only` while keeping `folder_name`) without nested `block_on`.

## Code map
- `crates/opendrive-app/src/lib.rs` — Exports `design`, `desktop`, `runtime`, and `shell` modules.
- `crates/opendrive-app/src/main.rs` — Synchronous binary entrypoint dispatching UI, interactive `authorize`/`mount`, `--mount-watchdog`, or `runtime::cli` commands.
- `crates/opendrive-app/src/runtime/{cli,cli_commands,cli_self_check}.rs` — CLI parser (`dispatch`, `dispatch_bridge`, `status_cmd`, `list_root_with_base`), Explorer/stream subcommands (`cli_commands.rs`), and self-contained `--self-check`.
- `crates/opendrive-app/src/runtime/{media_server,explorer_batch,explorer_ops,explorer_file_ops,explorer_helpers,explorer_open}.rs` — `MediaStreamServer`, `BatchOutcome`, `ExplorerEntry`, `ResolvedOpenTarget`, Explorer sync/file-op (`delete`/`rename`/`copy`/`move` + CLI `rm`/`rename`/`cp`/`mv` + batch helpers)/stream/open operations, `update_open_with_rules`, `remove_open_with_rule`, and Windows tree dehydration.
- `crates/opendrive-app/src/runtime/{bridge,bridge_types,bridge_vault,ui,mod}.rs` — `Bridge`, `AppStateResponse`, vault export/import, and persistent runtime builders (`stream_cache` wiring).
- `crates/opendrive-app/src/runtime/mount_manager/{mod,backend,live,sync_ops,virtual_drive}.rs` — `MountBackend`, `NullMountBackend`, `LiveMountBackend`, `cleanup_os_mounts`, `cleanup_os_mounts_for_pid`, `is_foreign_mount_owner_alive`, `install_process_mount_guards`, `spawn_mount_watchdog`, multi-account mount lifecycle, and `ExplorerQuota` / `This PC` namespace sync.
- `crates/opendrive-app/src/runtime/auth_runner/{mod,complete,endpoints}.rs` — `AuthEndpoints` (pickers + launcher), `AuthSession`, and OAuth/Service Account completion.
- `crates/opendrive-app/src/shell/tray_loop.rs` — Optional (`tray` feature) system tray loop (calling `MountManager::shutdown_all` on `TrayAction::Quit`).
- `crates/opendrive-app/tests/{bridge_ui_tests,cli_and_explorer_cov_tests,media_stream_and_cli_tests,mount_manager_tests,review_fixes_tests,runtime_cli_coverage_tests,runtime_cov_extra_tests,runtime_coverage_tests,runtime_explorer_cov_tests,runtime_vault_cov_tests,ui_and_cli_cov_final_tests}.rs` & `crates/opendrive-app/tests/support/mod.rs` — Integration tests for `Bridge`, `MountManager`, `MediaStreamServer` (`HEAD`/`200`/`206`/`416`/`403`/`404`), `StreamCache`, vault backup flows, and `runtime::cli` subcommands.
