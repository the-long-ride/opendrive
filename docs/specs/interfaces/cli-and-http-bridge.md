# CLI Commands, Synchronous Control Bridge, and Auth Runners

## Purpose and boundaries
Provides the `opendrive` binary CLI, the shared synchronous `Bridge` connecting `AppController` (`opendrive-core`), `SyncEngine` (`opendrive-sync`), `SecretStore` (`opendrive-auth`), and `MountManager`, background desktop authentication runners (`auth_runner`), persistent directory/store initialization helpers (`ui.rs`), and the optional `tray` runner.

- **In scope**: Synchronous CLI argument dispatch (`"" | "ui"`, `--self-check`, `authorize`, `list-root`, `status`, `mount`, `tray`, `help`); lazy Tokio runtime construction strictly for async subcommands, background `auth_runner` threads, and `MountManager` sync/mount runtimes; synchronous `Bridge` state snapshots (`bridge_types.rs`), secret store wiring, and mutations (`new_with_secrets`, `with_mount_manager`, `mounts`, `secrets`, `state_snapshot`, `add_account`, `account_action`, `update_settings`, `update_virtual_drive`, `evict_cache`, `saved_oauth_credentials`, `complete_oauth_account`, `complete_service_account`, `spawn_mount_sync`, `take_mount_notice`); `MountBackend` (`NullMountBackend`, `LiveMountBackend`) & `MountManager` (`mount_manager.rs`, `mount_manager/live.rs`, `mount_manager/sync_ops.rs`); `AuthEndpoints`, `AuthSession`, `start_browser_oauth`, `start_service_account_auth`; system tray loop (`tray_loop.rs`).
- **Out of scope**: OAuth PKCE / Service Account JWT primitives (`opendrive-auth`), Drive HTTP transport (`opendrive-drive`), OS VFS adapters (`opendrive-fs-*`), and `eframe`/`egui` widget rendering (`desktop*.rs`, `icons.rs`, `widgets*.rs`).

## Observable behavior

### CLI Entrypoints (`main.rs`)
- **Default (`""` or `"ui"`)**: Runs `ui::run_desktop_ui(load_controller())` synchronously without spawning any Tokio runtime threads, launching the native `eframe` desktop window directly.
- **Async CLI commands (`run_async`)**: Initializes a multi-threaded Tokio runtime on demand for `--self-check`, `authorize <client_id> <client_secret>`, `list-root <access_token>`, and `mount <access_token> [path]`.
- **`mount_cmd` / `mount_platform`**: Seeds the root node (`root`), hydrates the root folder, spawns `engine.spawn_worker(5s)` and `engine.spawn_change_poller(acct, 30s)`, and on Windows creates `<mount_path>/<account_name>` and calls `CloudFilesFrontend::connect_live_at(&root_str, account_name, root, tokio::runtime::Handle::current())` (unregistering on Ctrl+C).
- **`authorize <client_id> <client_secret>` (`authorize_cmd`)**: Runs browser PKCE OAuth (`AuthClient::authorize`), queries `DriveClient::about()`, creates or reuses a `"Desktop OAuth"` `CredentialSet` (`client_id`) in `credentials.json`, stores `client_secret` via `store_client_secret` and `refresh_token` via `store_refresh_token` in the OS keyring, links `credential_set_id`, and saves the `Account` to `config_dir()`.
- **`status`**: Loads persisted settings/accounts from `config_dir()` and prints account count, status, email, ID, and config path.
- **`tray`** (only with `--features tray`): Runs `crate::tray_loop::run_tray` with `opendrive_platform::default_menu()` actions (`OpenFolder`, `PauseAll`, `ResumeAll`, `Quit`).
- **`help` / `--help` / `-h`**: Prints supported CLI subcommands.

### Synchronous Bridge & Secret Wiring (`bridge.rs`, `bridge_types.rs`, `ui.rs`)
- `Bridge::new_with_secrets(settings, engine, config_dir, secrets)` constructs a `Bridge` backed by a caller-supplied `Arc<dyn SecretStore>` and defaults `mounts` to `Arc::new(MountManager::new_null())`; `Bridge::with_data_dir` and `Bridge::data_dir` track `<data_dir>` (used to store/load cached account avatars); `Bridge::with_mount_manager` replaces `mounts` and `Bridge::mounts()` exposes `&Arc<MountManager>`. `Bridge::new_with_engine` and `Bridge::new` default to `Arc::new(MemorySecretStore::new())`. `Bridge::secrets()` exposes `&Arc<dyn SecretStore>`.
- `Bridge::state_snapshot(&self)` reads `VfsEngine::stats(&*self.engine)` synchronously via `engine_stats_sync` (`Waker::noop()`), queries `cache_bytes_total`, resolves `self.mounts.mount_root()` (falling back to `"~/OpenDrive"`), and snapshots controller accounts and settings into `AppStateResponse`.
- `Bridge::add_account` validates non-empty trimmed `nickname`, falls folder name back to `nickname` when empty, marks empty-email accounts as `NeedsReauth` (otherwise `Connected`), persists to `config_dir`, and calls `engine.seed_root_account`.
- `Bridge::account_action` handles `pause_all`, `resume_all`, and UUID-validated `pause`, `resume`, `remove`, and `toggle_readonly`, returning descriptive `String` errors on missing/invalid IDs, unknown accounts, unknown actions, or persistence failures. When `action == "remove"` succeeds, it calls `self.secrets.delete_account_secrets(id)` to delete stored refresh tokens and service account JSON.
- `Bridge::update_settings` updates `cache_max_size`, `bandwidth_limit`, `autostart`, and `docs_mode`, updates `engine.set_bandwidth_limit`, invokes `opendrive_platform::set_autostart`, and persists settings. `Bridge::update_virtual_drive(enabled)` updates `settings.virtual_drive_enabled`, persists `settings.json`, and returns the updated `AppStateResponse`.
- `Bridge::spawn_mount_sync(repaint_ctx)` spawns a background thread invoking `mounts.sync_now(&ctrl, &engine, &secrets)`; on `Err`, `mounts.pending_notice` captures the error (`take_mount_notice`), and whenever `mount_one` updates `storage_used`/`storage_quota`/`avatar_url` or transitions an account missing credentials to `AccountStatus::NeedsReauth`, it persists `accounts.json` to `config_dir` (`take_mount_refresh` triggers UI state reload) and requests a repaint. Accounts lacking a valid `DriveClient` fail `mount_one` rather than spawning an unauthenticated poller.
- `Bridge::evict_cache` invokes `engine.evict_to(max_bytes)`.
- `ui::bridge_from_controller_with_secrets` restores all persisted `CredentialSet`s (`g.accounts.add_credential`) and `Account`s into the controller, seeds each account root in `SyncEngine`, and drains queued commands; `ui::bridge_from_controller` and `ui::build_bridge_in_dirs` default to `MemorySecretStore`, while `ui::build_persistent_bridge` calls `build_bridge_in_dirs_with_secrets` with `Arc::new(OsKeyringStore)` and attaches `Arc::new(MountManager::new_live())` and `with_data_dir(dirs.data.clone())`.

### Multi-Account Mount Manager (`mount_manager.rs`, `mount_manager/live.rs`, `mount_manager/sync_ops.rs`)
- `MountBackend` abstracts OS mount preparation and activation: `prepare_root(path)`, `connect_account(acct, path, root_node, engine, rt)`, `reconcile_placeholders(path, rel_dirs)`, `unregister_account(path)`, and `set_virtual_drive(enabled, letter, root)`.
- `NullMountBackend` is a headless no-op backend whose `set_virtual_drive` validates `opendrive_platform::normalize_drive_letter(letter)`.
- `LiveMountBackend` creates the root directory in `prepare_root`, calls `CloudFilesFrontend::connect_live_at(&path, &acct.nickname, root_node, rt.clone())` on Windows (`#[cfg(windows)]`; no-op on non-Windows) in `connect_account`, delegates `reconcile_placeholders` to `opendrive_fs_windows::reconcile_placeholder_dirs` so stuck pre-existing placeholder folders re-enable on-demand hydration, and delegates `set_virtual_drive` to `opendrive_platform::{mount_virtual_drive, unmount_virtual_drive}` (treating unsupported non-Windows unmount as `Ok(())`).
- `MountManager` (`new`, `new_null`, `new_live`, `with_mount_root`, `with_token_url`, `with_drive_urls`, `data_dir_or_default`, `mount_root`, `mounted_ids`, `is_virtual_drive_active`, `sync_now`):
  - `sync_now(&ctrl, &engine, &secrets)` acquires `sync_mutex`, snapshots accounts/credentials/settings, resolves `mount_root()`, and calls `unmount_stale` (dropping `MountedAccount` entries for paused, removed, or folder-renamed accounts, which aborts their `poller` `JoinHandle<()>` and calls `backend.unregister_account`).
  - `sync_virtual_drive(&settings, &root)` unmounts the previous drive letter if changed, then applies `backend.set_virtual_drive(enabled, &letter, root)` and updates `last_virtual_drive`.
  - If any accounts are `enabled && AccountStatus::Connected`, `sync_now` lazily builds a multi-threaded Tokio runtime, starts `engine.spawn_worker(5s)` once, and calls `mount_one` per unmounted target: creates `<root>/<folder_name>`, calls `engine.seed_root_account`, refreshes OAuth (`AuthClient::refresh`) or Service Account (`ServiceAccountKey::fetch_access_token`) access tokens via `SecretStore` when no `DriveClient` is registered, refreshes `About` storage quota & downloads profile photo via `cache_account_avatar`, hydrates the root folder (`engine.hydrate_folder`), connects via `backend.connect_account(..., root_node, ...)`, reconciles pre-existing placeholder dirs via `backend.reconcile_placeholders`, and spawns `engine.spawn_change_poller(acct.id, 30s)`.

### Desktop Auth Runners & Account Completion (`auth_runner.rs`, `auth_runner/complete.rs`)
- `AuthEndpoints` configures `auth_url`, `token_url`, `drive_api_base`, `drive_upload_base`, `redirect_timeout_secs` (default `180`), `browser_opener: BrowserOpener` (default `opendrive_platform::open_path`), and `folder_opener: BrowserOpener` (default `opendrive_platform::open_path`).
- `AuthSession` exposes `mode: ConnectAuthMode`, `target_account: Option<Uuid>`, `auth_url: Option<String>`, `try_recv() -> Option<AuthEvent>`, and `cancel()` (signals an internal `oneshot::Sender<()>`).
- `start_browser_oauth(bridge, endpoints, params, repaint_ctx)` spawns a worker thread with a single-threaded Tokio runtime that generates PKCE + CSRF state, binds `127.0.0.1` loopback, emits `AuthEvent::BrowserReady { auth_url, copy_to_clipboard: params.copy_link }`, optionally invokes `(endpoints.browser_opener)(&auth_url)` (emitting `AuthEvent::BrowserOpenWarning` on failure without aborting), awaits redirect or cancellation, exchanges the authorization code, queries `DriveClient::about()`, persists credentials/account (or updates `params.target_account_id` in place) via `Bridge::complete_oauth_account`, hydrates the root folder (`hydrate_folder`), and emits `AuthEvent::Completed` (or `AuthEvent::Failed`).
- `start_service_account_auth(bridge, endpoints, params, repaint_ctx)` spawns a worker thread with a single-threaded Tokio runtime that parses `ServiceAccountKey::from_json_or_path(&params.json_or_path)`, overrides `token_uri` with `endpoints.token_url` when `key.token_uri == DEFAULT_TOKEN_URI`, calls `key.fetch_access_token(params.read_only)`, queries `DriveClient::about()`, persists or updates (`params.target_account_id`) account + raw JSON via `Bridge::complete_service_account`, hydrates the root folder, and emits `AuthEvent::Completed` (or `AuthEvent::Failed`).
- `Bridge::save_oauth_client_credentials(client_id, client_secret)` creates or reuses a `"Desktop OAuth"` `CredentialSet`, persists `credentials.json` to `config_dir`, and calls `self.secrets.store_client_secret(cred_id, client_secret)` (surfacing any keyring error); `Bridge::credentials_for_account(account_id)` checks the account's `CredentialSet` secret (then any sibling `CredentialSet` matching `client_id` with a saved secret, then `OPENDRIVE_CLIENT_SECRET`), preserving `client_id` when secret lookup is empty; `Bridge::saved_oauth_credentials()` searches credentials newest-first for a paired non-empty secret before env fallback.
- `Bridge::finish_or_update_account` updates an existing `Account` in place when `target_account_id: Some(id)` matches (preserving `id`, `nickname`, `folder_name`, and `read_only`, flipping `status = Connected`, `enabled = true`, refreshing `credential_set_id`/`email`/`storage_used`/`storage_quota`/`avatar_url`, and returning `"Re-authenticated {nickname}"`), or creates a new `Connected` `Account` when `None`.
- `Bridge::complete_oauth_account` persists credentials via `save_oauth_client_credentials`, stores `refresh_token` in `self.secrets` under the final account ID, updates or adds the `Account`, saves accounts/credentials to `config_dir`, registers the `DriveClient` on `self.engine`, and seeds the root folder.
- `Bridge::complete_service_account` stores `raw_json` via `self.secrets.store_service_account_json(account_id, raw_json)`, updates or creates a `Connected` `Account` (`credential_set_id: Uuid::nil()`), saves to `config_dir`, registers the `DriveClient` on `self.engine`, and seeds the root folder.
