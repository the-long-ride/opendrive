# Design Spec: Built-in Drive Explorer, Localhost HTTP 206 Streaming, Open-With Rules & Clean This PC Quota

**Date:** 2026-11-25
**Status:** Implemented & Verified (`ER-1`..`ER-8` Proven)

## 1. Overview & Chosen Design (Approach A)

OpenDrive adopts **Approach A: Built-in Full-Viewport Drive Explorer + Localhost HTTP/1.1 `206` Range Streaming Server + Driverless Windows `This PC` Namespace** on top of the existing `SyncEngine` + SQLite `Store` + driverless OS VFS stack:

1. **Full-Viewport Drive Explorer & Per-Account Session Persistence (`desktop/explorer/**`, `desktop/explorer_actions.rs`, `desktop/ledger/row.rs`)**
   - Clicking **Explore** (`IconKind::Explore`, `UiAction::OpenExplorer(id)`) on any account card switches `ControlCenterApp::render_root` into a full-viewport split Explorer view (`render_explorer_panel`), while **Dashboard** (`UiAction::CloseExplorer`) returns cleanly to the Bento overview.
   - `ExplorerState::sessions: HashMap<Uuid, AccountExplorerSession>` preserves per-account `breadcrumbs`, `entries`, `selected_id`, `search_query`, and `loaded` flags across account switches in the left sidebar.
   - Main pane supports clickable breadcrumb navigation, live search filtering, `List` / `Grid` view toggles (`ExplorerViewMode`), colored vector `MediaKind` icons (`icons_media.rs`), `Sync State` pills (`Local` / `Dirty` / `Conflict` / `Syncing` / `Cloud`), UTC timestamps (`format_modified_date`), drag-and-drop file/folder uploads (`handle_explorer_drop`), double-click / `Enter` folder entry or item opening, and right-click context menus.
2. **Explicit Replica Sync Controls with Safety Invariant #3 (`replica_ops.rs`, `replica_upload.rs`, `replica_clear.rs`, `explorer_ops.rs`)**
   - **Sync Down (`sync_down_node` / `explorer_sync_down`)**: Downloads files atomically via `.tmp` rename into the mounted account root or cache directory, registers `cache_files` (`pinned = true`, `NodeState::Cached`), recurses into subfolders, and reconciles Windows CFAPI placeholder directories on mounted accounts.
   - **Sync Up (`sync_up_local_path` / `explorer_sync_up`)**: Uploads selected local files or recursive directories (creating remote Google Drive folders via `application/vnd.google-apps.folder`) and flushes pending queued account uploads (`flush_account_uploads`).
   - **Sync Up & Clear Local (`sync_up_and_clear_local` / `explorer_sync_up_and_clear`)**: Enforces **Safety Invariant #3** in two strict phases — Phase 1 uploads any dirty/local/staged bytes and verifies a non-empty remote `drive_id` (aborting immediately on HTTP/network failure without touching local files); Phase 2 removes regular non-reparse local replicas, staging files, `cache_files` rows, stream cache chunks, resets folders to `NodeState::Placeholder`, and dehydrates Windows CFAPI placeholders (`try_dehydrate_placeholder`).
3. **Localhost HTTP/1.1 `206` Streaming Server & `2 MiB` Chunked `StreamCache` (`stream_cache.rs`, `stream_store.rs`, `media_server.rs`)**
   - `MediaStreamServer` binds `127.0.0.1:0` with a per-session random bearer path token (`http://127.0.0.1:<port>/stream/<token>/<node_id>/<encoded_name>`).
   - Handles `GET` and `HEAD` requests with token & node validation (`403 Forbidden`, `404 Not Found`), `Accept-Ranges: bytes`, `Cache-Control: no-store`, `Content-Type` resolution (`content_type_for`), and `parse_http_range` (`bytes=start-end`, `bytes=start-`, `bytes=-suffix`, returning `206 Partial Content`, `200 OK`, or `416 Range Not Satisfiable`), streaming `512 KiB` pieces via `SyncEngine::read_cached_range(..., READ_AHEAD_CHUNKS = 3)`.
   - `StreamCache` caches `2 MiB` chunks (`STREAM_CHUNK_BYTES = 2 * 1024 * 1024`) in both a 24-entry in-memory LRU (`MemChunkLru`) and disk `<stream_cache>/<node_id>/<chunk_idx>.chk` keyed by `.rev` revision fingerprint.
   - `prewarm_head_and_tail` concurrently fetches chunk `0` and the tail chunk (`tokio::join!`) so MP4/MOV `moov` atoms at either end of the file resolve immediately on playback start; `read_cached_range` performs per-`(node_id, chunk_idx)` single-flight coalescing (`InFlightMap`) and background `read_ahead_chunks` prefetching throttled through `BandwidthLimiter`. `VfsEngine::read` also routes through `read_cached_range(..., 2)` after `StagingDir`.
4. **OS Default + Custom Open-With Format Rules (`open_rules.rs`, `open_rules_ui.rs`, `explorer_helpers.rs`)**
   - `Settings::open_with_rules: Vec<OpenWithRule>` (`#[serde(default)]`) matches extension lists (`mp4,mkv`), semantic groups (`@video`, `@image`, `@pdf`, `@audio`, `@code`, `@archive`), or wildcard (`*`) via `resolve_open_app`.
   - Settings modal includes **Open With Rules (Custom Format Apps)** with native `app_exe_picker` browse, add, and remove controls persisted to `settings.json`.
   - `explorer_open_item` (`explorer_open.rs`) routes:
     - `NativeDoc` -> Google Docs web URL (`DriveClient::native_doc_link`).
     - `Video` -> local cached file only when `node.state != NodeState::Placeholder`; otherwise pre-warms head/tail and serves the `MediaStreamServer` URL directly to streaming-capable custom players (`supports_http_stream_arg`: `vlc`, `mpv`, `iina`, `ffplay`, `mpc-hc`, `potplayer`, etc.), syncs down for non-streaming custom players, uses the mounted CFAPI placeholder path when mounted with OS default, or writes a fallback `<cache>/streams/stream-<node_id>.m3u` playlist when unmounted with OS default.
     - Other binary files (images, PDFs, audio, code/docs) -> cached file or automatic `explorer_sync_down` followed by `launch_with_app`.
5. **Driverless Windows `This PC` Namespace & Clean Quota Guard (`explorer_quota.rs`, `virtual_drive.rs`, `avatars.rs`, `bento.rs`, `sidebar.rs`)**
   - `compute_accounts_quota` and `compute_explorer_quota` inspect **all** configured accounts and return `None` whenever empty or any account reports `storage_quota == 0` or `storage_quota < storage_used`, hiding misleading `0 / 0` labels and bars in Windows `This PC` (`OpenDrive` instead of `OpenDrive (used / total)`), `Storage & Workspace`, account ledger rows, and the Explorer sidebar.
   - `sync_this_pc_namespace` registers/cleans up a driverless `HKCU` shell folder shortcut under `MyComputer\NameSpace` pointing at the OpenDrive root folder with `opendrive.ico` and optional tile quota comment (`cleanup_legacy_subst` unmounts any legacy `subst` mapping).
6. **Headless Explorer, Sync, File Ops & Streaming CLI Subcommands (`runtime/cli.rs`, `cli_commands.rs`, `cli_self_check.rs`)**
   - Includes `explore`, `sync-down`, `sync-up`, `sync-clear`, `open-item [--dry-run]`, `stream [--probe]`, `rename`, `rm|delete`, `cp|copy`, `mv|move`, plus `--self-check`.

## 2. Trade-off Summary

| Dimension                       | Approach A: Built-in Explorer + Localhost `206` Stream + Driverless `This PC` (Chosen)               | Direct REST Temp Downloads                           | WinFsp / Dokan Kernel Driver                         |
| ------------------------------- | ---------------------------------------------------------------------------------------------------- | ---------------------------------------------------- | ---------------------------------------------------- |
| **Driver / Admin Privileges**   | Zero kernel drivers or admin UAC required (`CFAPI` / `NFSv3` / `FUSE3` + `HKCU` namespace)           | Zero drivers                                         | Requires signed kernel driver install & reboot/UAC   |
| **Video Start & Seek Latency**  | Instant start & scrubbing via `2 MiB` chunk cache, head+tail `moov` pre-warm, and `206` range server | Must download full video to `%TEMP%` before playback | Fast byte-range reads, but tied to OS shell & driver |
| **Multi-Account Isolation**     | Dedicated per-account `AccountExplorerSession` state + isolated CFAPI roots                          | Manual temp folder management                        | Separate mount points / drive letters per driver     |
| **Custom App Launch Control**   | Built-in `OpenWithRule` pattern/group matching + direct HTTP URL pass-through to `vlc`/`mpv`         | Relies only on OS file extension associations        | Relies only on OS file extension associations        |
| **Quota & Safety Invariant #3** | Explicit `Sync Up & Clear` with remote `drive_id` verification + accurate quota hiding               | Ad-hoc temp cleanup risks losing unsaved edits       | OS shell delete/dehydrate semantics vary by Explorer |
| **Maintenance & Footprint**     | Pure Rust across workspace crates; zero new Cargo dependencies added                                 | Simple HTTP code, poor UX for large media            | High cross-OS maintenance & CI driver signing cost   |
